# 批量处理的设计取舍

本页记录各段实现方式与不采用其他方式的原因，与 README 第 3 节的参数口径对应。

## 1. 为什么要有 manifest（清单）

单个场景算 NDVI，失败了重跑一次就完事；一百个场景，重跑就是一百次网络请求和几十分钟。所以每景处理完立刻落一条记录：

```json
{
  "scene_id": "S2C_48RVU_20251201_0_L2A/S2C_48RVU_20251201_0_L2A",
  "status": "done",
  "params_hash": "3f9a…",
  "inputs": { "…_B04.tif": "a1b2…", "…_B08.tif": "c3d4…" },
  "stats": { "ndvi_mean": 0.482, "valid_frac": 0.962, … },
  "elapsed_s": 41.2
}
```

三个字段共同决定"要不要重跑"：

| 字段 | 变了意味着 |
|---|---|
| `inputs` 指纹（字节数 + 前 1 MB 的 sha1） | 换了影像文件 → 必须重跑 |
| `params_hash`（参数 + 工具版本的 sha1） | 改了 scale/offset/阈值 → 必须重跑 |
| `status` | 上次失败 → 必须重跑 |

**为什么指纹不取全文件 sha1**：100 MB 的影像全量哈希要几十秒，一个文件夹就是几十分钟，而"文件有没有变"用字节数 + 首 1 MB 已经够判断。这个取舍写在代码注释里，不是偷懒。

## 2. 为什么单景函数不许 print、不许 exit

`process_scene()` 只返回值，不写文件、不打印、不 `sys.exit`。好处有三个，缺一个都会在批量里翻车：

1. 能进进程池（`ProcessPoolExecutor` 要 pickle 函数和参数，带副作用的函数行为不可控）；
2. 能单独测试（12 个用例里有一半直接调它，不需要造一整个文件夹）；
3. 失败的原因能作为**返回值**带回上层记账，而不是变成"进程退出了但没人知道为什么"。

## 3. 为什么一景失败不终止整批

实际文件夹中常见零字节目录、投影混用、文件名缺波段。默认行为是：

- 失败的景 → `failures.csv` 一行（scene_id / stage / error_type / message / elapsed_s）
- 其余照跑
- 退出码 `3`（有失败），而不是 `0`（假装成功）或 `1`（一刀切）

要"全有或全无"就加 `--fail-fast`。

## 4. 为什么并发默认 1

取数是远程 COG 窗口读，瓶颈在网络；栅格计算是内存带宽，瓶颈也在 IO。两种情况加进程只会互相抢带宽。所以 `--workers` 留着，但默认 1，文档里写清"什么时候可以调大"（本地磁盘、影像已下载、单景足够大）。

## 5. 为什么不动人家的投影

`--grid-from` 默认为关闭。默认保持各景原网格；投影改变后与其他底图叠加会失配，因此统一网格需显式指定参考栅格。

## 6. 落账顺序（断电也不丢）

每景 -> 写 tif -> 写 manifest（临时文件 + `os.replace` 原子替换）。中途断电，最坏情况是"这一景算了但没记上"，不会出现"清单里写完成了但文件是坏的"。

## 7. 本版未实现的功能

- 不做大气校正（用的是 L2A，已经做过地表反射率校正）
- 不做镶嵌（多景拼一张不是本工具的目标，需要时走 GDAL）
- 不做 L1C（要自己算大气，超出范围）
- 不做云检测算法（只用 SCL，sen2cor 的粗分类够用）

## 8. 两个把人坑到的口径决定（都是复核时发现的）

### 8.1 小孔填补默认关掉

初版默认 `--fill-max-px 2.5`，逻辑是"离有效像元 2.5 像元以内的空值，用最近的有效值补上"。看起来只是消掉掩膜麻点，实测却出了问题：

- 用一份**独立写的最小脚本**（numpy 直接算，不经过 `processor`）复核 09-25 那景：工具给"有效 19.0%、均值 0.505"，独立脚本给"有效 7.75%、均值 0.433" —— **差 11 个百分点**。
- 原因就是填孔：云区被打散成很多小斑，2.5 像元的搜索半径把大片云下像元用邻值"补"成了有效像元，均值也被拉高。

结论：填孔等于在云区生成非观测值，会改变统计量。因此默认设为 0，`summary.csv` 记录 `fill_max_px`，图注按实际取值书写。需要时显式传入 `--fill-max-px`，结果应注明填补像元比例。

### 8.2 掩膜为什么坚持"两波段都为正"，而不是只看分母

同一个复核过程里试过一版"只看分母 > 0.002"：暗像元全被放进来，NDVI 直接爆表 —— 四景均值变成 1.39 / 2.64，最大值 70。因为 L2A 的 −0.1 偏移会把深色地表压在 0 附近，分母极小，比值被放大到几十。

所以口径定为：`DN>0` 且 `ρred>0.002` 且 `ρnir>0.002` 且 `ρred+ρnir>0.002` 且 `SCL ∉ 无效类`。代价是**暗景会掉大量像元**（demo 里 10-15 那景红波段中位反射率 −0.033，只剩 19.7% 有效像元），这是有意的取舍：宁可少算，不给假值。

该口径同时写入 README 第 6 节与图注。
